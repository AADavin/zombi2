# Joining

Conditioning works because the driver can be finished first. Sometimes it cannot:

- Body size decides how fast a lineage splits, and body size evolves along the very tree it is shaping.
- Carrying a key gene decides which lineages diversify, and gene content evolves along that same tree.

Growing the trait first would need a tree that does not exist yet; growing the tree first would need the trait. Neither can go first, so they go together, in one run, and the species tree stops being an input and becomes an output. The test is one question: *can the driver be grown on its own and handed over?* If it can, condition. If it cannot, **join**.

## The three parts, without the order

![The shape of a joint run, and why the ordering is gone. Body size drives speciation through the same `scaled_by`, but the rate it drives is what creates the tree, and that tree is the one the trait is evolving along, so the arrow returns. It returns from the *tree*, not from the rate: a speciation rate does not change a body size, it decides which lineages split, and each split hands the parent's trait state to both daughters. Compare the conditioning figure in Chapter 9, where the tree is a fixed input and so does not appear at all.](figures/joining_print.png){width=95%}

A joint run still has a driver, a target and a connection, written exactly as in Chapter 9. What changes is that the driver cannot be handed over, because it does not exist yet. So it is **named** instead, and the run grows it alongside the level that reads it.

There is nothing to write to a file, either, because the file would have to be written onto a tree that does not exist. Both levels are grown by one Gillespie, racing every kind of event against every other. A speciation reads the trait state on the lineage it happens on, which is what makes its rate depend on the trait; an extinction does the same; a trait change moves one lineage to another state and leaves the tree alone. When a speciation occurs, both daughters start from the parent's state. No approximation is needed: these drivers change only *at* events, so between two events every rate holds steady, which is what a Gillespie step already assumes.

### What can be joined

![What can be joined. Every arrow has two heads, because neither level can be finished before the other starts: a joint pair still has a driver and a target, but no order to grow them in. Compare the figure at the head of this chapter, and the conditioning map in Chapter 9, where the arrows run one way. Solid arrows are the two joint models ZOMBI2 has, and both reach the species tree, which is what makes the tree an output of the run. A dashed arrow is a pair nothing rules out and nobody has written; a loop is a level joined to itself. Two pairs have no arrow at all.](figures/joining_map_print.png){width=88%}

ZOMBI2 has the two that reach the species tree, and they are the rest of this chapter. The other five on the map are empty: nothing rules them out, and the nearest one to reach is a gene family driving another gene family in one run, since the engine already reads each lineage's live gene content to drive speciation and would only have to point that read at a different rate.

Two pairs have no arrow, and neither is waiting to be built. The species tree and a sequence are not a joinable pair, because a sequence lives on a gene tree, which lives on the species tree, so joining those two would mean joining the genome as well. Nor are a sequence and a trait: either can be grown first and read by the other, which is conditioning, and a sequence never feeds back into a trait.

## The driver

A joint driver is a level growing beside this one, named as a string rather than handed over. Three names:

| Driver | What it reads | Mapping |
|---|---|---|
| `"trait"` | the lineage's current state | a table over the states |
| `"genomes:<family>"` | whether that family is there | a table over `present` / `absent` |
| `"genomes:count"` | how many genes the lineage has | a curve, or a `Scalar` |

The level itself is given as a **process spec** — `traits.discrete(...)` or `genomes.family(...)` — a description of a process still to be grown rather than a finished result. A spec keeps all of its own options, and one of them changes the model: `at_speciation=` (Chapter 8) gives the trait a chance of jumping *at* each split, so the daughters diverge at the moment they are born while how fast a lineage splits still depends on the state it is in. The trait's event log tells the two apart, `on_speciation` against `on_branch`.

Give one driver per run: `trait=` or `genome=`, never both. A family whose presence does the driving has to be named in the genome spec, with `family_names=`.

## The target

Only `birth` and `death`, the species rates. That is the whole list, and it is what makes the tree an output rather than an input: the driver decides which lineages split and which die, so it decides the shape of the tree it is evolving along.

Stop the run at a size with `n_extant=` or at an age with `total_time=`, and give one or the other. What comes back is a `JointResult` carrying **both** grown levels — `.species` always, and then either `.trait` or `.genome`, the same result objects the standalone commands return. They share one `complete_tree`, because there was only ever one tree. A joint run writes both levels too, each exactly as its own command would.

## Writing one

Body size makes large lineages speciate twice as fast as small ones, and go extinct half as often:

```python
from zombi2 import joint, traits
from zombi2.params import PerLineage

joint.simulate_joint(
    birth = PerLineage(1.0).scaled_by("trait", {"small": 1.0, "large": 2.0}),
    death = PerLineage(0.2).scaled_by("trait", {"small": 2.0, "large": 1.0}),
    trait = traits.discrete(states=["small", "large"], switch=0.1),
    n_extant = 100, seed = 1)
```

Gene content instead, with the driving family named in the spec:

```python
from zombi2 import genomes

joint.simulate_joint(
    birth  = PerLineage(1.0).scaled_by("genomes:toxin", {"present": 1.8, "absent": 1.0}),
    death  = 0.2,
    genome = genomes.family(duplication=0.2, loss=0.25, origination=0.5,
                            family_names=["toxin"]),
    n_extant = 100, seed = 1)
```

Conditioning folds into the driven level's own command; joining cannot, because there is no level to run first, so it has a command of its own. The rate is written exactly as in Python, and the flags that build the driver are the ones `zombi2 traits` or `zombi2 genomes` would take. Giving flags from both is an error rather than a silent choice between them.

```bash
zombi2 joint out/ --death 0.2 --states small,large --switch 0.3 \
    --n-extant 100 --seed 1 \
    --birth "PerLineage(1.0).scaled_by('trait', {'small': 1.0, 'large': 3.0})"

zombi2 joint out/ --origination 0.2 --loss 0.1 --family-names toxin \
    --n-extant 60 --seed 1 \
    --birth "PerLineage(1.0).scaled_by('genomes:toxin', {'present': 3.0, 'absent': 1.0})"
```

## Literature

The state-dependent models arrive under a wall of acronyms, and a reader who wants "a BiSSE model" should be able to find the door.

| What it does | ZOMBI2 | From the literature |
|---|---|---|
| a binary trait drives speciation (and extinction) | `birth`, `death` `= PerLineage(…).scaled_by("trait", {…})` | BiSSE [@maddison2007bisse] |
| a multi-state trait drives speciation | the same, with more states in the table | MuSSE [@fitzjohn2012diversitree] |
| a trait drives speciation **and** jumps at the split | the same, plus `traits.discrete(at_speciation=…)` | ClaSSE [@goldberg2012classe] |
