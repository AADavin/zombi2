# Joining

Conditioning works because the driver can be finished first. Sometimes it cannot.

Suppose body size decides how fast a lineage splits. The trait evolves *along* a tree, and that same tree is the one the trait is shaping. Growing the trait first would need a tree that does not exist yet. Growing the tree first would need the trait. Neither can go first, so they go together, in one run.

That is **joining**, and the test for it is one question: *can the driver be grown on its own and handed over?* If it can, condition (Chapter 9). If it cannot, join.

## How one run grows two levels

There is nothing to write to a file, because the file would have to be written onto a tree that does not exist yet. So both levels are grown by one Gillespie, which races every kind of event against every other kind.

Three things can happen. A **speciation** reads the trait state on the lineage it fires on, which is what makes its rate depend on the trait. An **extinction** does the same. A **trait change** moves one lineage to another state and leaves the tree alone. When a speciation fires, both daughters start from the parent's state.

The race needs no approximation. These drivers change only *at* events, so between two events every rate holds steady, and a steady rate is what a Gillespie step already assumes. Out come both levels at once.

## What can be joined

Two levels have to be joined when neither can be finished first, and the map below is of the pairs where that is true.

Solid arrows are the two joint models ZOMBI2 has, and both reach the species tree, which is what makes the tree an output of the run. ZOMBI2 has the two that reach the species tree, and they are the subject of the rest of this chapter. The other five on the map are empty. Nothing rules them out, and the nearest one to reach is a gene family driving another gene family in one run: the engine already reads each lineage's live gene content in order to drive speciation, so the read exists and would only have to point at a different rate.

Two pairs have no arrow, and neither is waiting to be built. The species tree and a sequence are not a joinable pair, because a sequence lives on a gene tree, which lives on the species tree — joining those two would mean joining the genome as well. Nor are a sequence and a trait: either can be grown first and read by the other, which is conditioning (Chapters 7 and 9), but a sequence never feeds back into a trait, so there is nothing for the two to decide together.

## A trait drives speciation

A body-size state makes large lineages speciate twice as fast as small ones. The trait enters as a **process spec**, `traits.discrete(...)`, rather than as a finished run: it is a description of a process still to be grown, not a result.

```python
from zombi2 import joint, traits, genomes
from zombi2.params import PerLineage

joint.simulate_joint(
    birth = PerLineage(1.0).scaled_by("trait", {"small": 1.0, "large": 2.0}),
    death = 0.2,
    trait = traits.discrete(states=["small", "large"], switch=0.1),
    n_extant = 100, seed = 1)
```

Give `death` the same verb and extinction depends on the state too. A birth *and* a death that both read the trait is the model the literature calls BiSSE, or MuSSE with more than two states.

The spec keeps all of its own options, and one of them changes the model. `at_speciation=` (Chapter 8) gives the trait a chance of jumping *at* each split, so the daughters diverge at the moment they are born, while how fast a lineage splits still depends on the state it is in. The trait's event log tells the two apart: a jump at a split is recorded as `on_speciation`, a change along a branch as `on_branch`.

## Gene content drives speciation

The presence of a key gene — a toxin, a transporter — lifts a lineage's speciation rate, and the genome and the tree grow together. The genome enters as a process spec in the same way, and the family whose presence does the driving has to be named in it.

```python
joint.simulate_joint(
    birth  = PerLineage(1.0).scaled_by("genomes:toxin", {"present": 1.8, "absent": 1.0}),
    death  = 0.2,
    genome = genomes.family(duplication=0.2, loss=0.25, origination=0.5,
                            family_names=["toxin"]),
    n_extant = 100, seed = 1)
```

The driver names a level growing beside this one rather than a file, which is what makes the run joint. There are three to name:

| `driver` | What it reads | Mapping |
|---|---|---|
| `"trait"` | the lineage's current state | a table over the states |
| `"genomes:<family>"` | whether that family is there | a table over `present` / `absent` |
| `"genomes:count"` | how many genes the lineage has | a curve, or a `Scalar` |

A count is a number rather than a name, which is why it takes a curve: `scaled_by("genomes:count", lambda n: math.exp(0.02 * n))` makes gene-rich lineages speciate faster along a smooth response. All three drive `birth`, `death`, or both. Give one driver per run — `trait=` or `genome=`, never both.

Stop the run at a size with `n_extant=` or at an age with `total_time=`, exactly as in Chapter 3, and give one or the other. What comes back is a `JointResult` carrying **both** grown levels: `.species` always, and then either `.trait` or `.genome`, the same result objects the standalone commands return. They share one `complete_tree`, because there was only ever one tree — the one they grew between them.

## On the command line

Conditioning folds into the target level's own command. Joining cannot, because there is no level to run first, so it has a command of its own. The driver is named in the rate exactly as in Python, and the flags that build the driver are the ones `zombi2 traits` or `zombi2 genomes` would take.

```bash
# BiSSE: 'large' lineages speciate three times as fast as 'small' ones
zombi2 joint out/ --death 0.2 --states small,large --switch 0.3 \
    --n-extant 100 --seed 1 \
    --birth "PerLineage(1.0).scaled_by('trait', {'small': 1.0, 'large': 3.0})"

# state-dependent extinction too, by driving --death as well
zombi2 joint out/ --states small,large --switch 0.3 --n-extant 100 --seed 1 \
    --birth "PerLineage(1.0).scaled_by('trait', {'small': 1.0, 'large': 3.0})" \
    --death "PerLineage(0.2).scaled_by('trait', {'small': 2.0, 'large': 1.0})"

# gene content drives it: carrying the 'toxin' family triples the speciation rate
zombi2 joint out/ --origination 0.2 --loss 0.1 --family-names toxin \
    --n-extant 60 --seed 1 \
    --birth "PerLineage(1.0).scaled_by('genomes:toxin', {'present': 3.0, 'absent': 1.0})"
```

`--states` builds the trait driver and the gene-content flags build the genome one. Giving flags from both is an error rather than a silent choice between them. `--at-speciation` is the trait spec's jump-at-the-split, so ClaSSE is one flag away:

```bash
zombi2 joint out/ --death 0.2 --states small,large --switch 0.3 --at-speciation 0.3 \
    --n-extant 100 --seed 1 \
    --birth "PerLineage(1.0).scaled_by('trait', {'small': 1.0, 'large': 3.0})"
```

## Literature

The state-dependent models arrive under a wall of acronyms, and a reader who wants "a BiSSE model" should be able to find the door. The names live here, in one table, and organise nothing else in the chapter.

| What it does | ZOMBI2 | From the literature |
|---|---|---|
| a binary trait drives speciation (and extinction) | `simulate_joint`: `birth`, `death` `= PerLineage(…).scaled_by("trait", {…})` | BiSSE [@maddison2007bisse] |
| a multi-state trait drives speciation | the same, with more states in the table | MuSSE [@fitzjohn2012diversitree] |
| a trait drives speciation **and** jumps at the split | the same, plus `traits.discrete(at_speciation=…)` | ClaSSE [@goldberg2012classe] |

## Outputs

Joining adds no format. A joint run writes **both** the levels it grew, each exactly as its own command would: the species files, and then the trait files or the genome files depending on which level was in the race. The tree is written complete as well as extant, so the extinct lineages whose fate the driver decided are kept. Appendix B gives the columns and the formats.
